# Cartly Web Marketing Pages

Last updated: 2026-05-18
Status: canonical
Purpose: content and structure contract for landing, privacy, and support pages
Use this doc when: editing public copy, CTA structure, or proposal-facing web storytelling

## 1. 페이지 구성
현재 public marketing pages는 아래 3개를 기준으로 본다.
- landing `/`
- privacy `/privacy`
- support `/support`

## 2. landing 페이지 목적
landing은 단순 “앱이 있어요”가 아니라 아래를 동시에 만족해야 한다.
- 제품이 무엇인지 빠르게 설명
- 왜 믿을 수 있는지 보여줌
- proposal 링크처럼도 쓸 수 있음
- 실제 앱 주요 기능을 스크린샷과 함께 보여줌

## 3. landing 페이지 현재 구조

### hero
- 짧은 제품 정의
- 앱 버전 뱃지
- CTA
- 짧은 핵심 포인트

### feature preview
현재 다루는 기능 예시:
- 상품 스캔
- 현재 카트
- 저장한 장보기 기록
- 대체안 다시 보기
- 내 정보와 가족공유
- 로그인과 회원 시작

원칙:
- feature preview는 실제 앱 화면과 매칭되어야 한다.
- 설명은 screenshot과 같은 기능을 말해야 한다.

### status / trust
- 현재 운영 상태
- guest/member/family share 등 제품 경계
- 외부 링크가 사용자 탭 이후에만 열린다는 점

## 4. privacy 페이지 목적
privacy는 법적 문서이면서 제품 설명이기도 하다.
아래 내용이 충돌 없이 유지되어야 한다.
- 무엇을 수집하는지
- 어디에 쓰는지
- 위치는 foreground-only인지
- 외부 링크는 언제 열리는지
- 문의 이메일은 무엇인지

## 5. support 페이지 목적
support는 App Review와 실제 사용자 문의를 동시에 감당해야 한다.
따라서:
- reachable email이 보여야 하고
- 제품명/운영 상태와 어긋나지 않아야 하며
- privacy와 상호 일관적이어야 한다.

## 6. public copy 운영 규칙
- 문장은 짧게
- 주장보다 사실 위주
- 실제 제품 단계와 어긋나는 표현 금지
- beta, 정식 서비스 같은 라벨은 감정적 포장보다 실제 version 표기를 우선

## 7. 제안서 용도 기준
이 페이지는 앞으로 외부 제안 material처럼도 쓰일 수 있다.
그래서 다음을 중시한다.
- trust
- structure
- concise persuasion
- screenshot-backed explanation

## 8. CTA 규칙
- 첫 CTA는 기능 보기/구조 이해 중심이 적합
- 무리한 전환 유도보다 제품 이해를 우선
- privacy/support는 숨기지 말고 쉽게 닿게 둔다.
