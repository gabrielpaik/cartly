# Cartly App Product

Last updated: 2026-05-18
Status: canonical
Purpose: product definition, scope, and current feature contract for the customer app
Use this doc when: deciding what Cartly is, what it is not, and what the live product flow should do

## 1. 제품 한 줄 정의
Cartly는 **장보기 흐름을 기록하고, 같은 구매 의도 안에서 더 나은 선택을 다시 검토하게 도와주는 앱**이다.

## 2. 제품이 해결하는 문제
기존 장보기는 아래 문제가 있다.
- 지금 담는 물건과 지난 장보기 기록이 이어지지 않는다.
- 스캔/영수증/메모가 서로 분리되어 있다.
- 실제 구매 후 무엇을 샀는지와 다음 선택 후보가 연결되지 않는다.
- 가족과 같이 장봐도 현재 카트 협업이 어렵다.

Cartly는 이 문제를 다음 흐름으로 묶는다.
1. 상품을 스캔하거나 직접 추가한다.
2. 현재 카트를 만든다.
3. 저장된 장보기 기록으로 남긴다.
4. 영수증으로 실제 구매 결과를 정리한다.
5. Explore에서 같은 의도의 대체안을 다시 본다.
6. 필요하면 가족과 공유한다.

## 3. 제품 경계

### Cartly가 아닌 것
- 일반 커머스몰
- 장바구니 결제앱
- 무작위 광고 피드 앱
- 배달/주문 앱

### Cartly가 맞는 것
- 장보기 기록 앱
- 가격/상품 스캔 보조 앱
- 구매 후 회고까지 연결되는 장보기 도우미
- 같은 구매 의도 기반 대체안 탐색 도구

## 4. 핵심 사용자 상태

### 1) 게스트
- 로그인 없이 사용 가능
- 현재 카트, 저장 카트, 기본 탐색 가능
- 가족공유/프로필 수정/탈퇴는 불가

### 2) 회원
- 닉네임/계정 관리 가능
- 저장 기록과 장보기 흐름 연속성 강화
- 가족공유 사용 가능
- 탈퇴 가능

### 3) 가족공유 회원
- 저장 카트와 현재 카트를 household 단위로 협업 가능
- owner / member 역할이 존재

## 5. 주요 앱 표면

### Home
역할: 실행
- 현재 카트 관리
- 새 상품 추가
- 최근 스캔 확인
- 카트 저장

### Explore
역할: 판단
- 같은 구매 의도 기준 대체안 검토
- 반복 구매 후보 확인
- 저장 흐름에서 다시 보기
- 매장/프로모션 문맥 연결
- generic 추천 피드가 아니라 decision surface 유지

### Saved / 지난 카트
역할: 기록 허브
- 저장된 장보기 기록 재열람
- 같은 카트를 다시 시작
- 구매 완료 흐름 회고

### My
역할: 계정 + 기록 + 공유 허브
- 로그인/회원 상태 확인
- 개인정보 수정
- 가족공유 진입
- 위치 상태/개인정보 처리방침/문의

### Login
역할: 기록 연속성을 얻는 진입점
- 게스트 계속 사용 허용
- 이메일 기반 가입/로그인/비밀번호 재설정
- 회원 전용 기능을 위한 진입

## 6. 현재 핵심 기능 상태

### 상품 스캔
- 이미지 업로드/카메라 기반 스캔 지원
- 결과는 사용자 검토 후 현재 카트에 반영
- 실패/저신뢰 상태는 앱과 운영에서 모두 추적 가능

### 현재 카트
- 상품명/가격/수량 단위로 작업
- 수동 추가 가능
- 저장 시 saved cart로 이동
- 가족 household에 속한 회원은 shared current cart를 사용

### 저장 카트 / 구매 기록
- 저장 카트는 작업물이다.
- purchase-complete는 실제 구매 이력이다.
- 고객 UI에서는 purchase-complete를 노골적으로 드러내지 않고, 내부 로직과 운영에 주로 쓴다.

### 영수증 흐름
- 고객에게는 “영수증이 정답” 흐름을 제공한다.
- 비교 리뷰가 아니라 **receipt apply**가 핵심이다.
- 영수증 분석 후 저장 카트를 수정 적용할 수 있다.
- undo는 edit mode 안에서 제공한다.

### 위치 사용
- 목적: 근처 마트 할인정보 확인
- foreground only
- 앱 시작 시 1회, 쇼핑/스캔 시작 시 추가 1회 시도 가능
- 스캔 자체를 막지 않는다.
- 현재 raw location history는 로컬 우선이며, 서버 개인화 타게팅의 source of truth는 별도 고객/지역 모델로 본다.

## 7. Home / Explore 경계와 Explore 제품 규칙

### 한 줄 규칙
- Home = 실행
- Explore = 판단 / 재검토 / 재진입

### Home이 가져야 하는 것
- 스캔/추가/현재 카트/저장 같은 active shopping workflow
- 지금 행동해야 하는 일

### Explore가 가져야 하는 것
- 비교
- 다시 보기
- 같은 구매 의도 안의 대체안
- 저장 후 재검토
- store-context 프로모션 문맥

### 핵심 원칙
- Explore는 help 탭이 아니라 decision surface다.
- unrelated 추천 피드를 만들지 않는다.
- 같은 구매 의도 안의 대체안만 다룬다.

### Explore 상태 모델
- active shopping: 지금 담은 것, 지금 고민한 것을 중심으로 재검토
- post-save: 저장 후 다시 볼 후보와 반복 구매 맥락 강화
- idle planning: 다음 장보기 전 재열람과 후보 정리
- store-context: 특정 마트/지역 문맥이 강할 때 관련 행사/프로모션 연결

### 대체안 후보의 근거
- 현재 카트에 담은 상품
- 담았다가 뺀 상품
- 스캔했지만 담지 않은 상품
- 저장 기록 / 반복 구매 힌트

## 8. 카트와 영수증에 대한 제품 규칙

### 저장카트 vs 구매이력
- 저장카트는 mutable한 작업물이다.
- 구매완료는 실제 구매 증거다.

### 구매완료 판단
- 2일 동안 수정 없으면 구매완료
- 영수증 등록 후 저장카트 치환 시 즉시 구매완료

### 날짜 노출 규칙
고객 화면 날짜는 아래 우선순위를 따른다.
1. 영수증 `purchasedAt`
2. 원래 저장/스캔 생성 시점
3. 단순 수정 시점은 대표 날짜로 쓰지 않는다.

## 9. 가격/제목/카테고리 규칙

### 제목
- 저장 카트 제목과 영수증 적용 제목은 같은 톤으로 맞춘다.
- 영수증 적용 후 제목은 `매장명 + 구매일` 형식을 우선한다.

### 가격
- 고객 수동 입력은 한 개 가격 필드만 유지한다.
- 할인/정가 분리는 신뢰 가능한 소스가 있을 때만 메타데이터로 저장한다.

### 카테고리
- `기타` 남용을 피한다.
- 음식/신선식품은 식품 우선 분류가 기본이다.
- 사용자가 직접 카테고리를 수정할 수 있다.

## 10. 현재 회원 기능
- 닉네임 변경
- 비밀번호 재설정/변경
- 가족공유 생성/참여/해제/나가기
- 회원 탈퇴

## 11. 현재 비회원과 회원의 구분

### guest / non-household
- 현재 카트는 local only
- 가족공유 불가

### member + household
- shared current cart 사용
- shared saved/past cart 가시화
- household 상태가 세션 변경 시 올바르게 정리되어야 함

## 12. 제품 KPI 관점의 핵심 흐름
- guest 진입 → 현재 카트 작성 → 저장
- member 전환 → 저장 흐름 지속
- receipt apply → 구매 기록 품질 향상
- Explore 재진입 → 같은 의도 대체안 검토
- household 협업 → 다인 장보기 지속성 강화

## 13. 지금 기준 열린 과제
- 실제 기기에서 최신 상단 로고 fallback 빌드 확인
- App Store / Google Play 최종 제출 마무리
- Explore/광고/세그먼트의 실제 운영 성과 연결 고도화
